# Лабораторная работа 14 (скриншоты в 14.docx)
## На базе предыдущих лабараторных работ было создано приложение, в результате которого реализованы принципы SOLID:
- SRP (Single Responsibility): выделены отдельные классы для работы с сетью (PostApi, RetrofitClient), базой данных (NoteDao, AppDatabase) и отображением (PostListScreen). Нарушений нет, каждый класс отвечает за одну задачу.
- OCP (Open/Closed): при добавлении нового типа данных (например, загрузка комментариев к постам) достаточно создать новый PagingSource и интерфейс API, не изменяя существующие экраны и RetrofitClient.
- LSP (Liskov Substitution): проверено, что все реализации интерфейсов (например, PostApi, NoteDao) ведут себя предсказуемо, не выбрасывают неожиданных исключений и не возвращают null там, где ожидается non-null тип.
- ISP (Interface Segregation): интерфейсы разбиты на узкие (PostApi отвечает только за GET-запросы, NoteDao — за CRUD операции). Клиенты (экраны) используют только нужные методы, не зависят от лишнего.
- DIP (Dependency Inversion): экраны Compose получают зависимости через параметры (например, dataSource: ProductDataSource), а не создают Retrofit или Room внутри. В NotesApp и RetrofitClient реализованы синглтоны, которые внедряются вручную (без Dagger/Hilt, но с соблюдением инверсии).
